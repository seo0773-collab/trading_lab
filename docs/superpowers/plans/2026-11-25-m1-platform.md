# M1 플랫폼 + EMA/RSI 페이퍼 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 스펙(규칙 ID) → 코드 → 테스트가 CI로 묶인 상태에서, EMA/RSI 전략을 한·미 주식 페이퍼 계좌로 매일 자동 운용하고, 검토 세션 PR → 머지 → VM 자동 반영 루프를 1회 완주한다.

**Architecture:** 하루 1회(시장별) `run_cycle`이 일봉으로 ① 대기 주문을 당일 시가에 체결 ② 당일 저가로 손절 확인 ③ 종가로 다음 날 주문 결정 → 리스크 가드 → 페이퍼 브로커 대기열. 백테스트는 같은 `run_cycle`을 과거 날짜로 반복한다. VM에서는 systemd 타이머가 CLI를 호출하고, updater가 `lab/main`을 테스트 통과 시에만 반영하며, 요약 데이터를 `lab/ledger` 브랜치로 push한다.

**Tech Stack:** Python 3.12, pandas, numpy, pyyaml, pykrx(한국 일봉), yfinance(미국 일봉), pytest, GitHub Actions, systemd.

**Spec:** `docs/superpowers/specs/2026-11-25-trading-lab-design.md`

## Global Constraints

- Python 3.12. 런타임 의존성은 `pandas numpy pyyaml pykrx yfinance` 만. 테스트는 `pytest`. 그 외 추가 금지.
- 테스트는 네트워크를 쓰지 않는다(가격 소스는 주입·monkeypatch).
- 시간대: 모든 날짜 판단은 `Asia/Seoul`. 시장별 일봉 날짜는 해당 시장 현지 거래일 그대로 쓴다.
- 스펙 규칙 형식: `- **<PREFIX>-<N>**: <문장>` (정규식 `^- \*\*([A-Z]+-\d+)\*\*:`). 코드 참조: `# RULE: <ID>`. 테스트 이름: `test_<PREFIX>_<N>` 또는 `test_<PREFIX>_<N>_<설명>`.
- 스펙·코드·테스트는 같은 커밋/PR에서 함께 바뀐다. 매 태스크 끝에 `pytest -q`와 `python -m tlab.tools.check_rules` 둘 다 통과.
- 비용(편도): US 20.103bp, KR 1.46527bp, 슬리피지 5bp(불리한 방향). KR 매도 거래세 20bp — **[확인 필요] 2026년 실제 세율로 사용자 확인 후 조정**. 값은 `config/costs.yaml`.
- 페이퍼 초기 자본: KR 10,000,000 KRW, US 8,000 USD. 시장별 독립 계좌(환전 없음).
- 기록 금지 원칙: 메모·저널 파일을 만들지 않는다. 런타임 기록은 기계 판독 JSONL/JSON만.
- 데이터·상태 디렉터리는 저장소 밖: 환경변수 `TLAB_HOME`(기본 `~/tlab`). 그 아래 `data/cache`, `state`, `ledger`.

## Review Focus

1. 휴장일 또는 장 마감 직후 데이터가 아직 없음 → 그날은 아무 주문도 내지 않고, 다음 실행 때 빠진 날짜를 순서대로 따라잡는다. (Task 7 `test_SYS_3_catch_up_missed_dates`, `test_SYS_2_no_bar_no_orders`)
2. 시가가 손절가보다 아래로 갭 하락 → 손절가가 아니라 시가에 체결. (Task 6 `test_EXIT_3_gap_down_fills_at_open`)
3. 슬롯 금액보다 1주 가격이 비싼 종목(예: 고가 미국주) / 현금 부족 → 0주 주문은 만들지 않고 현금이 음수가 되지 않는다. (Task 4 `test_SIZE_1_zero_shares_skipped`, Task 6 `test_paper_never_negative_cash`)
4. updater가 받은 새 커밋의 의존성 설치나 테스트가 실패 → 기존 릴리스 유지 + 알림. (Task 9 `test_SYS_6_failed_tests_keep_current`)
5. 같은 날짜로 cycle이 두 번 실행(타이머 중복, 수동 재실행) → 두 번째는 아무것도 바꾸지 않는다. (Task 7 `test_SYS_4_rerun_same_date_is_noop`)

스펙 본문(`specs/strategies/ema_rsi_v1.md`) — 아래 규칙을 그대로 적는다. 목적 절: "루프 검증용 단순 추세 전략. 가치 축은 M2부터."

- **UNIV-1**: KR `005930, 000660, 042700`, US `NVDA, AMD, MU, AVGO, TSM` (반도체 — [제 판단] 사용자가 산업군을 정하면 이 규칙만 바꾼다).
- **DATA-1**: 일봉 60개 미만인 종목은 신호를 내지 않는다.
- **ENTRY-1**: 미보유 종목이 종가 > EMA50, EMA20 > EMA50, 50 ≤ RSI14 ≤ 70 이면 다음 개장 시가 매수.
- **EXIT-1**: 보유 종목 종가 < EMA50 이면 다음 개장 시가 매도.
- **EXIT-2**: 보유 종목 RSI14 > 80 이면 다음 개장 시가 매도.
- **EXIT-3**: 당일 저가 ≤ 진입가 × 0.92 이면 진입가 × 0.92에 매도. 시가가 이미 그 아래면 시가에 매도.
- **SIZE-1**: 매수 수량 = floor((시장 계좌 equity / 4) / 종가). 0주면 주문하지 않는다.
- **SIZE-2**: 빈 슬롯(4 − 보유 수)보다 후보가 많으면 EMA20/EMA50 비율이 큰 순으로 고른다.
- 알려진 한계 절: "가격은 무수정 주가 — 보유 중 액면분할 시 손익 왜곡."

**Files:**

`config/risk_limits.yaml`:
```yaml
max_position_weight: 0.25
max_positions: 4
daily_loss_limit: 0.03       # 시작 equity 대비 하락률 → 신규 매수 금지
max_drawdown_halt: 0.15      # peak 대비 → halted, 수동 재개까지 매수 금지
max_orders_per_day: 10
max_order_value: {kr: 5000000, us: 4000}
```

`specs/_system.md`에 추가:
- **RISK-1**: 매수 후 종목 비중이 equity의 `max_position_weight`를 넘는 주문은 거부한다.
- **RISK-2**: 보유 종목 수가 `max_positions`에 도달하면 매수를 거부한다.

`run_cycle` 처리 순서 (날짜 하나당, `broker.state["last_date"]` 다음 날부터 `today`까지 유니버스에 봉이 있는 날을 오름차순으로):
1. 해당 날짜 봉이 없으면 건너뜀. 하나도 없으면 `skipped=True`.
2. `fill_pending(opens)` → 원장 `fill`.
3. 보유 종목마다 `fill_stop(stop_price(p), open, low)` → 원장 `fill`.
4. `mark(closes)`; 날짜가 바뀌면 `day_start_equity`·`orders_today` 리셋; `should_halt`면 `halted=True` + 원장 `risk`.
5. `decide` → `guard` → 승인은 `submit`, 거부는 원장 `risk`. 원장 `signal`, `equity`.
6. `last_date` 갱신·저장.
데이터 로드 예외는 잡아서 그날 이후 처리를 멈추고(`error` 채움, 주문 없음) 상태는 직전 완료 날짜로 남긴다.
